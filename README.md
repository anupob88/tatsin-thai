# ตัดสิน

ตัดสินเป็นบริการจัดเส้นทางข้อความภาษาไทย ระบบอ่านข้อความ แล้วเลือกว่าจะส่งงานไปห้องใด หากหลักฐานไม่พอ ระบบจะงดตัดสินและส่งเข้าห้องกักเพื่อให้คนตรวจ

ตัดสินไม่ใช่ผู้ช่วยสนทนา ไม่เขียนคำตอบแทนผู้ใช้ และไม่ส่งงานออกไปเอง การนำผลไปใช้ต่อเป็นหน้าที่ของระบบที่เรียกบริการนี้

## สถานะก่อนใช้งาน

รุ่นนี้ยังไม่ผ่านเกณฑ์สำหรับงานอัตโนมัติที่ไม่มีคนกำกับ ผลทดสอบรวมล่าสุดคือ 17 จาก 25 กรณี โมเดลใหญ่และการเลือกเจ็ดห้องยังไม่มีผลทดสอบที่เพียงพอ จึงควรใช้เพื่อทดลองหรือทำงานเงาเท่านั้น

แพ็กเกจนี้มีชั้นครอบและตัวเสิร์ฟโมเดล แต่ไม่มีไฟล์น้ำหนักขนาดประมาณ 1.29 GB ต้องดาวน์โหลดน้ำหนักแยกและวางไว้ตามขั้นตอนด้านล่าง

รายละเอียดผลทดสอบและข้อจำกัดอยู่ใน [MODEL_CARD.md](MODEL_CARD.md)

## เริ่มใช้ในเครื่อง

ต้องมี Python 3.10 ขึ้นไป และไฟล์น้ำหนักของ `tatsin_v2`

### 1. วางน้ำหนัก

นำโฟลเดอร์น้ำหนักไปไว้ที่ตำแหน่งนี้:

```text
model_server/ckpt/tatsin_v2/
```

ในโฟลเดอร์ต้องมีไฟล์น้ำหนัก ตัวเข้ารหัส และตัวแบ่งคำครบตามชุดที่ได้รับมา

### 2. เปิดโมเดลเล็ก

```bash
cd model_server
python -m pip install -r requirements.txt
python decide_endpoint.py
```

ตัวเสิร์ฟจะเปิดที่ `127.0.0.1:8140` รายละเอียดเพิ่มเติมอยู่ใน [model_server/README.md](model_server/README.md)

### 3. ติดตั้งชั้นครอบ

เปิดหน้าต่างคำสั่งอีกหน้าต่างหนึ่ง แล้วรัน:

```bash
cd service
python -m pip install -r requirements.txt
```

### 4. ตั้งค่าที่จำเป็น

บน Linux หรือ macOS:

```bash
export TATSIN_SMALL_URL="http://127.0.0.1:8140/tatsin/decide"
export TATSIN_SMALL_NAME="tatsin_v2"
```

บน Windows PowerShell:

```powershell
$env:TATSIN_SMALL_URL="http://127.0.0.1:8140/tatsin/decide"
$env:TATSIN_SMALL_NAME="tatsin_v2"
```

### 5. เปิดบริการตัดสิน

```bash
python serve.py
```

ค่าเริ่มต้นคือ `127.0.0.1:8130` เครื่องอื่นจึงเรียกไม่ได้

ตรวจว่าบริการพร้อมทำงาน:

```bash
curl http://127.0.0.1:8130/health
curl http://127.0.0.1:8130/rooms
```

ถ้ายังไม่มีน้ำหนัก โมเดลเล็กจะใช้งานไม่ได้ และข้อความส่วนใหญ่จะไปห้องกัก

## ทดลองคำขอแรก

จากโฟลเดอร์หลักของแพ็กเกจ:

```bash
curl -X POST http://127.0.0.1:8130/decide \
  -H "Content-Type: application/json" \
  --data-binary @examples/sample_esp32.json
```

ควรส่งข้อความภาษาไทยผ่านไฟล์และใช้ `--data-binary` เพื่อหลีกเลี่ยงปัญหาการเข้ารหัสของเชลล์

คำขอขั้นต่ำมีรูปแบบดังนี้:

```json
{
  "state": "เขียนสคริปต์ดึงข้อมูลจากเอพีไอให้หน่อย"
}
```

ผลตอบกลับที่ควรสนใจ:

- `route` คือรหัสห้องที่เลือก
- `act` เป็น `route` เมื่อส่งต่อได้ หรือ `abstain` เมื่อต้องกักไว้ตรวจ
- `layer` บอกว่าผลมาจากกฎตัวตน โมเดลเล็ก โมเดลใหญ่ หรือห้องกัก
- `calls` คือจำนวนครั้งที่เรียกโมเดล
- `answer` เป็นชื่อห้องที่เลือก และเป็น `null` เมื่อระบบงดตัดสิน; ถ้า `layer` เป็น `identity` ค่านี้จะเป็นประโยคแนะนำตัว ส่วน `route` และ `room_label` จะเป็น `null`

ตัวอย่างผลตอบกลับ:

```json
{
  "route": "code",
  "answer": "ห้อง code",
  "act": "route",
  "layer": "small",
  "calls": 5
}
```

## เปิดให้เครื่องอื่นใช้อย่างปลอดภัย

ห้ามเปิดบริการออกนอกเครื่องโดยไม่ตั้งกุญแจรับเข้า

สร้างกุญแจที่คาดเดายาก แล้วเก็บไว้ในตัวแปรสภาพแวดล้อม ห้ามใส่กุญแจจริงใน `config.json` หรือไฟล์ที่ส่งขึ้นระบบควบคุมรุ่น

```bash
export TATSIN_API_KEY="<YOUR_KEY>"
python serve.py --host 0.0.0.0 --port 8130
```

ตัวอย่างสำหรับ PowerShell:

```powershell
$env:TATSIN_API_KEY="<YOUR_KEY>"
python serve.py --host 0.0.0.0 --port 8130
```

ผู้เรียกจากเครื่องอื่นต้องแนบหัวข้อ `X-Api-Key`:

```bash
curl -X POST http://SERVER_IP:8130/decide \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: <YOUR_KEY>" \
  --data-binary @examples/sample_esp32.json
```

การไม่ตั้งกุญแจเหมาะเฉพาะการเรียกผ่าน `127.0.0.1` ในเครื่องเดียว ตัวแอปต้องปฏิเสธคำขอจากที่อยู่อื่นเมื่อไม่มีกุญแจ แม้ผู้ดูแลจะเปิดด้วย Uvicorn โดยตรง

## ต่อโมเดลใหญ่

โมเดลใหญ่เป็นทางเลือก เมื่อไม่ตั้งค่า เคสที่โมเดลเล็กไม่มั่นใจจะไปห้องกักทันที

จุดเชื่อมต่อต้องรองรับรูปแบบ OpenAI และเส้นทาง `/chat/completions`

```bash
export TATSIN_BIG_URL="http://127.0.0.1:8000/v1"
export TATSIN_BIG_MODEL="your-big-model"
export TATSIN_BIG_KEY="<YOUR_PROVIDER_KEY>"
```

ตัวแปร `TATSIN_BIG_KEY` ใช้เฉพาะเมื่อผู้ให้บริการต้องการกุญแจ เก็บกุญแจไว้ในระบบจัดการความลับหรือตัวแปรสภาพแวดล้อมเท่านั้น

โมเดลใหญ่ต้องตอบข้อมูลในรูปแบบนี้:

```json
{"answer":"A","confidence":0.85,"act":"route"}
```

ถ้าความมั่นใจต่ำกว่าเกณฑ์ หรือรูปแบบคำตอบไม่ถูกต้อง ระบบจะส่งเคสไปห้องกัก

## ตั้งค่าห้อง

แก้ไฟล์ `service/config.json` ก่อนนำไปใช้จริง โดยตรวจอย่างน้อยสี่ส่วน:

1. ใส่ปลายทางจริงใน `rooms[].channel_id`
2. ใส่ปลายทางสำหรับ `quarantine.channel_id`
3. ตรวจจุดเชื่อมต่อโมเดลใน `endpoints`
4. แก้ประโยคแนะนำตัวใน `identity.answer_th` ให้ตรงกับงานของคุณ

ห้ามสลับลำดับ เปลี่ยนชื่อ หรือเพิ่มจำนวนห้องให้กับน้ำหนักเดิม ตัวอักษร A, B, C และลำดับห้องถูกผูกไว้ตั้งแต่ตอนฝึก หากต้องการชุดห้องใหม่ ต้องฝึกและทดสอบโมเดลใหม่

ค่าเกตใน `config.json` เป็นค่าที่ใช้กับผลทดสอบปัจจุบัน อย่าปรับเพื่อให้ผ่านง่ายขึ้นโดยไม่มีชุดทดสอบใหม่รองรับ

## ห้องกัก

ห้องกักรับเคสที่ระบบไม่มีหลักฐานพอจะเลือกห้อง เช่น โมเดลใช้งานไม่ได้ อ่านตัวเลือกไม่ครบ ความมั่นใจต่ำ หรือโมเดลสองชั้นไม่เห็นตรงกัน

ระบบไม่ถามผู้ใช้ระหว่างตัดสิน แต่ผลในห้องกักต้องมีคนตรวจ ก่อนนำไปส่งต่อหรือทำงานภายนอก ห้ามตั้งระบบให้เคสที่กักไว้ดำเนินการเอง

## การปิดข้อมูลส่วนบุคคล

ก่อนส่งข้อความไปยังโมเดล ชั้นครอบจะปิดข้อมูลที่ตรงกับรูปแบบต่อไปนี้:

- เบอร์โทรศัพท์ไทย
- เลขบัตรประชาชน 13 หลัก
- ที่อยู่อีเมล
- เลขบัตรชำระเงิน 13 ถึง 16 หลัก

การปิดข้อมูลด้วยรูปแบบข้อความไม่ครอบคลุมข้อมูลส่วนบุคคลทุกชนิด หากงานมีข้อมูลอ่อนไหว ควรทดสอบด้วยข้อมูลขององค์กรและเพิ่มกฎที่จำเป็นก่อนใช้งานจริง

## ตรวจชุดทดสอบ

ชุดทดสอบของชั้นครอบไม่ต้องใช้น้ำหนักหรือเครือข่าย:

```bash
cd service
python -m unittest discover -s tests
```

หลังเปิดโมเดลเล็กแล้ว ให้ตรวจเคสอ้างอิง:

```bash
cd model_server
python smoke_test.py
```

ผลผ่านของชุดทดสอบไม่ได้เปลี่ยนสถานะความพร้อมผลิต ต้องดูผลชุดทดสอบแยกที่ระบุใน `MODEL_CARD.md` ด้วย

## แก้ปัญหา

| อาการ | สิ่งที่ควรตรวจ |
|---|---|
| ทุกข้อความไปห้องกัก | ตรวจ `/health` และดูว่าโมเดลเล็กเปิดอยู่หรือไม่ หากไม่ต่อโมเดลใหญ่ เคสที่โมเดลเล็กงดจะถูกกักทั้งหมด |
| ได้เหตุผล `no_coverage` หรือ `partial_coverage` | โมเดลเล็กไม่ได้รายงานจำนวนตัวเลือก หรืออ่านตัวเลือกไม่ครบ |
| ได้เหตุผล `noul_missing` | จุดเชื่อมต่อไม่ได้ส่งสัญญาณงดที่น้ำหนักรุ่นนี้ต้องใช้ |
| ข้อความไทยเพี้ยน | ส่งเนื้อหาผ่านไฟล์ด้วย `--data-binary` |
| ได้รหัส 401 หรือ 403 | ตรวจ `TATSIN_API_KEY` และหัวข้อ `X-Api-Key` |
| โมเดลตอบห้องผิดช่วง | ตรวจจำนวน ลำดับ และชื่อห้องให้ตรงกับตอนฝึก |
| คำขอช้าและคิวอื่นรอ | รุ่นนี้ประมวลผลทีละคำขอ เหมาะกับปริมาณงานต่ำ |

## จุดเชื่อมต่อของโมเดลเล็ก

ชั้นครอบเรียก `POST /tatsin/decide` โดยส่งข้อความ คำถาม และรายการห้อง ตัวเสิร์ฟต้องตอบอย่างน้อย `pick`, `confidence`, `noul`, `margin`, `coverage` และ `source`

ตัวอย่างผลตอบกลับ:

```json
{
  "pick": "A",
  "confidence": 0.92,
  "noul": 0.119,
  "margin": 0.80,
  "coverage": {"scored": 7, "requested": 7},
  "source": "tatsin_v2"
}
```

หาก `coverage.scored` น้อยกว่า `coverage.requested` หรือไม่มี `coverage` ระบบจะงดตัดสิน หาก `source` ไม่ตรงกับรุ่นที่กำหนด ระบบจะไม่ใช้เกตเฉพาะของ `tatsin_v2`

## โครงสร้างแพ็กเกจ

```text
tatsin-thai/
├── README.md
├── MODEL_CARD.md
├── LICENSE
├── NOTICE
├── service/
├── model_server/
└── examples/
```

- `service/` มีชั้นครอบ จุดเรียกใช้งาน การตั้งค่า และชุดทดสอบ
- `model_server/` มีตัวเสิร์ฟโมเดลเล็ก แต่ไม่มีน้ำหนัก
- `examples/` มีตัวอย่างคำขอ
- `MODEL_CARD.md` มีผลทดสอบและข้อจำกัด
